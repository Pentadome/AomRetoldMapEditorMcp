# Custom campaign mods (editor_build_campaign)

Served by `editor_help topic=campaign`. Full-only tool; no game connection.

- **Fast path:** `editor_build_campaign {"scenarios":[{"sourcePath":"latest"}]}` previews a mod from the newest saved `.mythscn` under the profile `scenario\` folder (skipping `~testing*` and `AomMcp-checkpoint*`). `modName` defaults to the scenario's folder (or file stem), `campaignId` to its lowercase `[a-z0-9_]` form, `displayName` to `modName`, titles to file stems. Apply with the returned `applyArgs` plus `preview:false, confirmWrite:true` (and `confirmDestructive` + a new `backupDirectory` when any file is `replace`). `latest` is preview-only; apply always uses the resolved path and `expectedSha256`.
- **Layout written** under `<profile>\mods\local\<modName>\`: `game\campaign\<id>\<id>.xml` (ordered CampaignNodes, each visible scenario requires the previous; `cinematic:true` = hidden node), byte-identical scenario copies, `game\data\strings\<lang>\stringmods.txt` (new mods: `english`; update reuses the mod's single existing strings folder, e.g. `language`).
- **XS bundling (`bundleXs`, default true):** every player `aiPath` (all non-Gaia slots, any control) and every TR XS Scripts entry, plus include closures, is resolved profile → existing mod → stock install. Profile files are copied mirroring the profile layout at the mod root: profile `Game\AI\<rel>` → `game\ai\<rel>`, profile `trigger\<rel>` → `trigger\<rel>` (the layout of the user's working om10 fix; the `trigger\` location is not separately verified against `game\data\trigger\`). Stock AI (loose `game\ai`) and stock trigger scripts (inside `game\data\Data.bar`) are never copied. Stock files' own includes are not walked. Trigger-script includes resolve against trigger roots (assumption).
- **Self-containment:** preview reports `selfContained` (true/false/null when PL/TR could not be decoded), `missingFromMod` (file, referencing player/script/include, reason), per-scenario `dependencies`. Apply refuses `MOD_NOT_SELF_CONTAINED` (retry-safe, nothing written) unless `allowIncomplete:true`. This is file resolution only; XS compile/runtime is not checked.
- **operation=create** (default) needs a NEW mod folder. **operation=update** refreshes an existing mod: each planned file is `create`, `replace` or `unchanged` (hash-equal). Replacing needs `expectedInstalled:[{path,sha256}]` exactly matching the preview, `confirmDestructive:true` and a NEW `backupDirectory` outside the mod; the original is backed up, the new bytes staged beside the target, re-verified and swapped in, then read back. Update never deletes: extra files are listed as `unmanaged` (e.g. a stale XS left from an earlier layout) for the user to remove by hand. No ownership receipts: only planned paths are touched, and replacements are hash-pinned.
- Failures after writing start return `CAMPAIGN_BUILD_OUTCOME_UNKNOWN` with retained paths: inspect, fix by hand, re-preview. Never retry blindly.
- Mods load at startup: restart the game and enable the mod. To prove self-containment, temporarily move the profile's `Game\AI\<folder>` and `trigger\<folder>` away and play the campaign with only the mod enabled. Publish/update through the in-game Mods → Publish flow; re-run with `operation=update` after every scenario/XS change.
