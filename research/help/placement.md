# Scene helpers, placement, coordinates and world tools

Moved verbatim from AGENTS.md; served by `editor_help topic=placement`.

- Inspect start state once. Use one final screenshot after known actions; intermediate screenshots only when next action depends on visible state. Pass `editor_screenshot`/`editor_overview` `resolutionScale` (0.1..1, default 1; e.g. 0.6 = 60% size, ~36% pixels) to cut token cost; map derived coordinates back to full-resolution client pixels. Batch `delayMs` can wait for a frame, but acknowledgements still do not prove effects.
- Prefer world-space scene helpers (core) over pixel placement: `editor_place_at_world` (world X/Z, catalog proto check with suggestions, minimap camera move, UI-panel avoidance, returns observed unitId/positionError), `editor_apply_layout` (items or world-unit formation; preview default, apply needs confirmPlacement, footprint issues refuse unless allowIssues), `editor_camera_look_at` (closed-loop minimap clicks, normal/alternative UI at 2560×1440 or 1920×1080), `editor_view_info`/`editor_ui_state` (visible ground bounds, panels, cursor), `editor_units_snapshot`+`editor_units_diff` (added/removed/moved/reidentified — undo/redo gives NEW IDs), `editor_scene_summary`, `editor_check_footprints`, `editor_terrain_grid` (heights, flat sites). `editor_delete_units` needs exact {unitId,proto,player} + confirmDestructive; selects via uiLookAtAndSelectUnit, verifies exact selection, DELETE, verifies removal. Raw `editor_place_unit` pixels over UI panels can still place on hidden map behind them. See `research/SCENE-TOOLS.md`.
- `editor_place_formation` defaults to pure preview. Spacing is client pixels, not world units; count cap32. Actual placement requires preview=false/confirmPlacement and observes IDs; partial effects remain on failure. `editor_save_checkpoint` requires approved new absolute .mythscn path/confirmWrite, unique game-writer staging and verification. No overwrite/retry/automatic rollback. Never exercise these mutations merely to test code on user's current scene without specific live-test authorization and backups.
- Greek infantry building is `MilitaryAcademy`, not Egyptian `Barracks`. Replacement observed with prototype selection → DELETE key → `editor_place_unit`; `uiTransformSelectedUnit(...,-1,false)` did not change selected barracks in that tested context. Do not waste repeated attempts on that unverified path.
- Coordinates are full-resolution client pixels. Multiply 1280-wide screenshot coordinates by two on 2560×1440, by 1.5 on 1920×1080 client. Reviewed layouts: `uilayouts/*-2560x1440.json` and `*-1920x1080.json` (1080: rects ×0.75 of 2560, gates re-sampled live; both UIs live-verified 1080 incl. OCR, player settings, diplomacy, camera, placement, paint/elevation). Other clients 1024..3840 wide with aspect 1.25..2.4 get an in-memory **derived** layout (since 2026-10-22: per-axis scaling, minimap uniform, dialog writers best effort; `research/UI-SCALING.md`; the 16:9 description below still applies at 16:9) (2560 geometry × height/1440, gates match either reviewed reference within 2 px, minimap gate tolerance 30), reported `layoutReviewed:false`: UI detection, occluders, camera look-at and OCR presets live-verified both UIs at 1600×900 and 1280×720 (720p alternative text OCR noisy: game clips glyphs; numbers fine). Derived mode treats conditional panels as present (smaller clickable area: e.g. 32×32 flatten refused TARGET_NOT_CLICKABLE at 1600×900 alt, 20×20 passed; split areas), enables palette selection with scaled 2560 list geometry, NOT live-tested at derived sizes (exact-name OCR before click + texture memory/mix label OCR after, so misses fail PAINT_TYPE_NOT_FOUND_IN_PALETTE; 720p text OCR weak; no native texture/mix setter exists, forest/water/cliff use native setters); 1600×900 both UIs live-verified place_at_world/apply_layout (error ≤0.04), delete_units, forest paint, elevation set/flatten; dialog writers (`editor_player_settings`/`editor_set_diplomacy` apply) and playtest stay pinned to reviewed sizes. Dropdown menus (File/Scenario/"...") do NOT scale with resolution (fixed ~34 px rows). Other aspect ratios fail closed.
- World helpers (core, `research/LIVE-WORLD.md`): `editor_edit_mode` reads mode/UI kind/paint selections and `exit=true` leaves any tool (PlaceUnit needs two `editMode("None")`). `editor_paint_world` paints texture/mix/water/forest/cliff along world points (confirmDestructive; current brush; verified tile/object diff). `editor_elevation` set/flatten/smooth an area (brush centers on lower-left node of tile under pointer; edges can bleed ~2 nodes, reported). `editor_transform_unit` moves (moveunit drag) and rotates (`uiRotateSelection` = ±22.5° per call, magnitude ignored). `editor_terrain_info`, `editor_live_players` (no resources: obfuscated), `editor_terrain_catalog` (exact native names, lighting index→name, civ id→name), `editor_overview` (ID-annotated screenshot; hides helper/aura objects by default, reported in `hiddenHelpers`; `includeHelpers=true` draws them cyan, stacked with nearest regular object as `id/id`), `editor_camera_frame`, `editor_camera` (get/zoom/pitch/reset with readback; native zoom = distance to plane y=0; wheel: positive steps zoom in, clamped 29..85), `editor_capture` (fit a world area by zoom, image or `saveTo` new `.png`, camera restored; large areas: tile with several calls), `editor_resource_balance`, preview-first `editor_mirror_units`/`editor_scatter`. Map building (shapes, strokes, brush, projection, land analysis, map size, new scenario): `editor_help topic=map-building`.
- Placement failures (2026-10-22): `POINTER_NOT_SETTLED` (hover map never confirmed the pointer; nothing placed, retry), `PLACEMENT_NOT_OBSERVED` (`retrySafe:true` after a verified-unchanged rescan), `PLACEMENT_OFFSET` (object placed off target and the automatic move failed; result names the unit). A successful off-target placement is moved and reported as `correction`. `BRIDGE_REFUSED`/`NOT_IN_EDITOR` before any input are `retrySafe:true` (`effectsSent:0`). `GAME_BUSY`: another MCP process held the game input lock for 30 s.
- No UI detected or odd window size: `editor_ui_state diagnose=true` lists per-gate expected vs observed colours (`gateDiagnostics`).
