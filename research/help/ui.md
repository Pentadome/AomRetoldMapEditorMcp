# Normal vs alternative editor UI; removed native loadScenario

Moved verbatim from AGENTS.md; served by `editor_help topic=ui`.

- Native `loadScenario` tool and shipped expressions referencing it are removed: alternative-UI test crashed game after this call. Full mode/confirmation cannot re-enable it. Normal Load Scenario UI successfully loaded the same edited checkpoint and restored original backup after restart. Wait for loading to finish before scene reads; editor flag/acknowledgement alone does not prove readiness. Core alternative-UI flows tested, not full coverage or an alternative-specific crash cause; see `research/ALTERNATIVE-UI.md`.
- New UI-driving tools must support BOTH normal and alternative UI: detect UI by pixel gates, report `uiKind`, keep per-UI geometry in `uilayouts/`, live-verify each UI (or state untested one explicitly), never fail closed on one UI by design.
- Editor has two UIs: **normal** and **alternative**. Switch: main menu → Settings → UI → scroll to bottom → "Alternative Editor UI". Scene helpers auto-detect the UI from pixel gates (normal: top menu bar; `uilayouts/normal-en-2560x1440.json`) and report `uiKind`; minimap targeting/occluders/paint palette selection work in both at 2560×1440 or 1920×1080 (all four live-verified; derived sizes: see coordinates note, palette selection enabled but not live-tested). `editor_playtest` has profiles for both UIs at reviewed sizes. `editor_player_settings` and `editor_set_diplomacy` apply work in both (auto-detected, `uiKind` returned): normal UI pre-opens Scenario > Player Data / Scenario > Diplomacy (same stance grid/colors as alternative). `editor_ui_read` field presets work in both: it detects the open panel by pixel gates (normal: Scenario > Player Data, its Age Settings popup, AI Set Load Menu; alternative: Players Settings) and reports `uiKind`; normal UI has no `color` preset. Normal UI docks tool panel + list palette along the bottom; PlaceUnit opens them, so placement treats them as occluders.
