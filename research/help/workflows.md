# Saved-file workflows, AI install, runtime probes, playtest

Moved verbatim from AGENTS.md; served by `editor_help topic=workflows`.

- `editor_unit_notes` (core and full) and full-only `editor_scenario_diff` are saved-file reads, not live identity/complete semantic proof. Saved-file readers (`editor_unit_notes`, `editor_scenario_diff`, `editor_players`, `editor_scenario_digest`, `editor_xs_check`) accept `"latest"` (newest save in the active profile `scenario` folder, excluding `~testing*`/`AomMcp-checkpoint*`; result echoes `resolvedFrom`, `sha256`, `modifiedUtc`) and take optional hash pins; pin the echoed hash when a later write depends on it. `editor_unit_notes` adds `noteGroups` (case/space/typo variants merged over the whole filtered set; digits must match) and `liveMatch=true` (needs the editor: current unit with the same ID within 0.5 world XZ on the page; evidence, not identity proof). `editor_scenario_digest` adds the scenario's XS Scripts list, per-player `missingIncludes` and a trigger summary from the embedded TR when `triggerPath` is omitted. Diff assertions evaluate all records before paging. `editor_trigger_edit` typed replacements check full ordered ID/owner/proto tuples; cross-trigger copies read immutable pinned sources and use stable handles/original insertion indices. `editor_startup_orders` audits explicit saved pools and preserves jobs; minimum-distance XZ assignments are not pathfinding/runtime proof and write only new TR files. `editor_install_ai` previews first and restricts writes to profile `<id>\\Game\\AI\\aom_mcp`; updates need pinned ownership receipt/old hash and external new backup/staging paths (`force=true` skips only the receipt, still inside `aom_mcp`). Never overwrite stock/unregistered AI, elevate, retry or auto-clean retained artifacts. `editor_runtime_probe` generates opt-in own-context XS with fresh KB queries, no context switching/saved-ID dispatch; `aiEcho` file transport/compiler proof unconfirmed. `editor_runtime_report` validates supplied hash/time/run-bound transcript facts, not authenticated engine evidence. `editor_playtest` registers four profiles `uilayouts/playtest-{alt,normal}-en-{2560x1440,1920x1080}.json` (English, Player1/Standard, exact build/hash/pixels; pick the one matching `uiKind`/client size from capabilities `profiles`); public start/inspect/token-bound normal menu Quit passed for each. Loading/defeat/external overlays/other profiles refuse; only host-token-authorized known-playing Quit uses narrow outside-editor input. Poll next gates before following clicks; never repeat queued input. Runtime offsets remain disabled; no debugger, memory writes or arbitrary native getters. See `research/SESSION-WORKFLOWS.md` and `research/RUNTIME-TELEMETRY.md`.
- Use UI Play/Quit for playtest transitions; one native start-test call crashed game. Read-only screenshots work during playtest; mutations remain editor-only.
- During a playtest editor reads answer `NOT_IN_EDITOR`. To see the whole map, type a chat cheat (Enter, code, Enter): `CLEAR SKIES` removes black map and fog of war (again re-enables), `LAY OF THE LAND` reveals the map. `start` returns them in `hints.cheats` once `playing`. Pass `expectedPid`/`expectedWindowThread` from `start` to `inspect`/`quit`/`dismiss`; verification gates tolerate ±10 per channel and 80% of pixels, result `gate` lists mismatches.
- Trigger compile errors are NOT in MythLog: Play shows a modal "Trigger Error." dialog instead. `editor_playtest start`/`inspect` read it (state `dialog`, `dialog.parsed[{file,line,code,message,hint,source}]`, `compileEvidence`); `dismiss` (token + confirmDismiss) clicks its OK and reports the next dialog or the playing gate. `trigtemp.xs(N)` lines map to `editor_xs_diagnostics operation=trigtemp`. Live-verified normal UI 2560x1440 only.
- `editor_build_campaign` packages saved scenarios and the profile XS they need (player AI + TR XS Scripts with includes) as a self-contained campaign mod; preview first, `operation=update` refreshes an existing mod with hash-pinned replacements. Details: `editor_help topic=campaign`.
