# Editor workflow: fast, guarded

- Keep one MCP host/stdio connection for each workflow. Group known operations in `editor_batch` (up to 32 steps); avoid one host/model turn per action.
- Default core exposes 74 tools (65 helpers + nine essential native commands). Always-visible `editor_toolset` inspects/switches core/full mid-session; full has 924 tools (including seven full-only session workflow helpers). Changes notify tools/list_changed: refresh tools/list without old cursor. Use standalone mode call, never inside editor_batch. Hidden calls/batch steps fail before effects. Tool sets are not permission sandboxes.
- Find tools from core with `editor_search_tools`: required nonblank `query` (max256), whitespace-separated case-insensitive terms across full-catalog names/descriptions; compact results include `available`/`requiredToolset`, no schemas. offset>=0, limit1..50 (default10); follow nextOffset. No game connection, mode change or match execution. Hidden matches require standalone full switch and fresh tools/list; availability is not runtime readiness.
- For unfamiliar native parameters, read `generated/catalog.json` or narrowly filtered `editor_catalog` (current set only). Switch full when needed; do not page full schema surface for one command. Immutable definitions cached within host.
- Missing/stale catalog metadata (`METADATA_*`/`FILE_NOT_FOUND` from catalog tools): run core `editor_generate_catalog` (no game connection; decodes installed archives with bundled CryBar from `lib/CryBarEditor` submodule; catalog tools reload without restart, new `action_*` tools need restart).
- Use `editor_pantheon` for exact culture-associated unit/building names (e.g. `greeks`), not guessed spellings/artwork. Metadata-only; no game connection. Union across gods/ages, not current-player trainability. Regenerate/restart if metadata missing/stale.
- Use filtered `editor_prototypes` for trees/resources/wildlife/decorations/other objects; `editor_gods`, `editor_technologies`, `editor_god_powers`, `editor_terrain_types`, `editor_water_types` for other source catalogs. Exact `name` or narrow `filter`; bounded `limit`, follow `nextOffset`. XML detail only when needed. Metadata-only batches need no game. Source names/flags are not runtime IDs or placement proof.
- Inspect start state once. Use one final screenshot after known actions; intermediate screenshots only when next action depends on visible state. Pass `editor_screenshot`/`editor_overview` `resolutionScale` (0.1..1, default 1; e.g. 0.6 = 60% size, ~36% pixels) to cut token cost; map derived coordinates back to full-resolution client pixels. Batch `delayMs` can wait for a frame, but acknowledgements still do not prove effects.
- Prefer world-space scene helpers (core) over pixel placement: `editor_place_at_world` (world X/Z, catalog proto check with suggestions, minimap camera move, UI-panel avoidance, returns observed unitId/positionError), `editor_apply_layout` (items or world-unit formation; preview default, apply needs confirmPlacement, footprint issues refuse unless allowIssues), `editor_camera_look_at` (closed-loop minimap clicks, normal/alternative UI at 2560×1440 or 1920×1080), `editor_view_info`/`editor_ui_state` (visible ground bounds, panels, cursor), `editor_units_snapshot`+`editor_units_diff` (added/removed/moved/reidentified — undo/redo gives NEW IDs), `editor_scene_summary`, `editor_check_footprints`, `editor_terrain_grid` (heights, flat sites). `editor_delete_units` needs exact {unitId,proto,player} + confirmDestructive; selects via uiLookAtAndSelectUnit, verifies exact selection, DELETE, verifies removal. Raw `editor_place_unit` pixels over UI panels can still place on hidden map behind them. See `research/SCENE-TOOLS.md`.
- Never guess unit IDs from placement order. Use `editor_units` / `editor_inspect_selection` for actual full live IDs/properties; IDs do not persist across reloads. `editor_map_info` gives measured projection/rays/native quantized heights, not terrain-collision or occlusion proof. These reads need reviewed optional layout sections; generator never guesses them.
- Use `editor_dependencies` for source train/build/tech/god paths; potential links, not evaluated current-player trainability. `editor_validate_scenario` is partial/read-only; caller-declared live IDs and supplied controller heuristics only, skipped checks explicit.
- `editor_triggers` structured support is strictly verified TR v12 single Always/CodeSnippet controller. Local patch requires new output/confirmWrite; apply requires confirmDestructive and retains original backup/round-trip files. Unknown shapes refuse; serialization equality is not XS compilation/effect proof.
- Native `uiLoadTriggers` / `uiSaveTriggers` / `saveScenario` receive filename stems, not suffixed filenames: game appends `.trg` / `.mythscn`. Raw trigger import/export require confirmDestructive. Unknown structured original triggers need separately authorized native backup restoration; helper apply does not guess their shapes.
- Selection and undo effects can be queued. Put `delayMs` on the **following read step**, then verify actual IDs/properties; do not repeat mutations from immediate acknowledgements. Placement cleanup clears cursor, but object palette can remain open; inspect before explicit ESC/UI restoration.
- `editor_place_formation` defaults to pure preview. Spacing is client pixels, not world units; count cap32. Actual placement requires preview=false/confirmPlacement and observes IDs; partial effects remain on failure. `editor_save_checkpoint` requires approved new absolute .mythscn path/confirmWrite, unique game-writer staging and verification. No overwrite/retry/automatic rollback. Never exercise these mutations merely to test code on user's current scene without specific live-test authorization and backups.
- Greek infantry building is `MilitaryAcademy`, not Egyptian `Barracks`. Replacement observed with prototype selection → DELETE key → `editor_place_unit`; `uiTransformSelectedUnit(...,-1,false)` did not change selected barracks in that tested context. Do not waste repeated attempts on that unverified path.
- Coordinates are full-resolution client pixels. Multiply 1280-wide screenshot coordinates by two on 2560×1440, by 1.5 on 1920×1080 client. Reviewed layouts: `uilayouts/*-2560x1440.json` and `*-1920x1080.json` (1080: rects ×0.75 of 2560, gates re-sampled live; both UIs live-verified 1080 incl. OCR, player settings, diplomacy, camera, placement, paint/elevation). Other 16:9 clients 1280..2560 wide get an in-memory **derived** layout (2560 geometry × height/1440, gates match either reviewed reference within 2 px, minimap gate tolerance 30), reported `layoutReviewed:false`: UI detection, occluders, camera look-at and OCR presets live-verified both UIs at 1600×900 and 1280×720 (720p alternative text OCR noisy: game clips glyphs; numbers fine). Derived mode treats conditional panels as present (smaller clickable area: e.g. 32×32 flatten refused TARGET_NOT_CLICKABLE at 1600×900 alt, 20×20 passed; split areas), enables palette selection with scaled 2560 list geometry, NOT live-tested at derived sizes (exact-name OCR before click + texture memory/mix label OCR after, so misses fail PAINT_TYPE_NOT_FOUND_IN_PALETTE; 720p text OCR weak; no native texture/mix setter exists, forest/water/cliff use native setters); 1600×900 both UIs live-verified place_at_world/apply_layout (error ≤0.04), delete_units, forest paint, elevation set/flatten; dialog writers (`editor_player_settings`/`editor_set_diplomacy` apply) and playtest stay pinned to reviewed sizes. Dropdown menus (File/Scenario/"...") do NOT scale with resolution (fixed ~34 px rows). Other aspect ratios fail closed.
- Batch preflights schemas/native confirmations and stops on first error; earlier effects remain. Never blindly retry mutations or entire batches. Keep every hash/thread/editor/foreground/selection guard.
- Use UI Play/Quit for playtest transitions; one native start-test call crashed game. Read-only screenshots work during playtest; mutations remain editor-only.
- Native `loadScenario` tool and shipped expressions referencing it are removed: alternative-UI test crashed game after this call. Full mode/confirmation cannot re-enable it. Normal Load Scenario UI successfully loaded the same edited checkpoint and restored original backup after restart. Wait for loading to finish before scene reads; editor flag/acknowledgement alone does not prove readiness. Core alternative-UI flows tested, not full coverage or an alternative-specific crash cause; see `research/ALTERNATIVE-UI.md`.
- New UI-driving tools must support BOTH normal and alternative UI: detect UI by pixel gates, report `uiKind`, keep per-UI geometry in `uilayouts/`, live-verify each UI (or state untested one explicitly), never fail closed on one UI by design.
- Editor has two UIs: **normal** and **alternative**. Switch: main menu → Settings → UI → scroll to bottom → "Alternative Editor UI". Scene helpers auto-detect the UI from pixel gates (normal: top menu bar; `uilayouts/normal-en-2560x1440.json`) and report `uiKind`; minimap targeting/occluders/paint palette selection work in both at 2560×1440 or 1920×1080 (all four live-verified; derived sizes: see coordinates note, palette selection enabled but not live-tested). `editor_playtest` has profiles for both UIs at reviewed sizes. `editor_player_settings` and `editor_set_diplomacy` apply work in both (auto-detected, `uiKind` returned): normal UI pre-opens Scenario > Player Data / Scenario > Diplomacy (same stance grid/colors as alternative). `editor_ui_read` field presets work in both: it detects the open panel by pixel gates (normal: Scenario > Player Data, its Age Settings popup, AI Set Load Menu; alternative: Players Settings) and reports `uiKind`; normal UI has no `color` preset. Normal UI docks tool panel + list palette along the bottom; PlaceUnit opens them, so placement treats them as occluders.
- World helpers (core, `research/LIVE-WORLD.md`): `editor_edit_mode` reads mode/UI kind/paint selections and `exit=true` leaves any tool (PlaceUnit needs two `editMode("None")`). `editor_paint_world` paints texture/mix/water/forest/cliff along world points (confirmDestructive; current brush; verified tile/object diff). `editor_elevation` set/flatten/smooth an area (brush centers on lower-left node of tile under pointer; edges can bleed ~2 nodes, reported). `editor_transform_unit` moves (moveunit drag) and rotates (`uiRotateSelection` = ±22.5° per call, magnitude ignored). `editor_terrain_info`, `editor_live_players` (no resources: obfuscated), `editor_terrain_catalog` (exact native names, lighting index→name, civ id→name), `editor_overview` (ID-annotated screenshot; hides helper/aura objects by default, reported in `hiddenHelpers`; `includeHelpers=true` draws them cyan, stacked with nearest regular object as `id/id`), `editor_camera_frame`, `editor_resource_balance`, preview-first `editor_mirror_units`/`editor_scatter`.
- Speed checks must not place/delete objects or change triggers. Existing build/self-test/protocol smoke cover code changes; no new framework needed.
- Start unfamiliar work with `editor_capabilities`. Errors carry `code`/`nativeDispatched`/`safeInspection`/`nextAction`; `*_OUTCOME_UNKNOWN` means stop and inspect retained paths. Campaign triggers: `editor_trigger_list` then preview-first `editor_trigger_edit` (expectedSha256+expectedName, new outputPath); `editor_triggers apply` also needs reviewed live export path/hash. Players: `editor_players`/`editor_player_dependency_audit` decode reviewed checkpoint fields; stances 1 ally, 2 enemy, 3 neutral. `editor_set_diplomacy` accepts directed matrix `changes` (one final checkpoint) as well as legacy oneWay/mutual. `editor_player_settings` previews/verifies offline; apply is pinned to 2560×1440 or 1920×1080 alternative Players Settings or normal Player Data, pixel/OCR gates, fresh checkpoint/TR backups and game-written final checkpoint. Normal UI live-verified: name/resources/pop/handicap, control/visibility, civ (scrolling list), color (`swatchRgb` sampled at x=88), start/max age, minor god, AI path (Set needs control Computer), and diplomacy matrix. Player `name` = editable display name (first PL string, `displayName` in `editor_players`). Normal text fields keep a blinking caret, so OCR gates re-read; startAge 0 may show "Default". MCP input refuses outside editor mode, so main-menu settings toggle required a temporary PID/foreground/size-guarded menu-only click helper, with MCP screenshots. Returning to Editor starts blank; restore backup via visible Load Scenario UI (never native `loadScenario`). After reload PL and embedded TR matched `step-03`; trigger export bodies and named camera entries matched too, with only the export-basename header changed. Exact viewport pose was not restored. Age changes auto-reset minor gods: require `observedOnly` assertions for all three; AI Name UI typing did not persist, but guarded file browser can reselect INSTALLPATH `game\ai` XS and verify checkpoint. OCR '9' may read as '6' or reversed—checkpoint is authoritative, never retry blindly.
- Full-only `editor_unit_notes`/`editor_scenario_diff` are hash-pinned saved-file reads, not live identity/complete semantic proof. Diff assertions evaluate all records before paging. `editor_trigger_edit` typed replacements check full ordered ID/owner/proto tuples; cross-trigger copies read immutable pinned sources and use stable handles/original insertion indices. `editor_startup_orders` audits explicit saved pools and preserves jobs; minimum-distance XZ assignments are not pathfinding/runtime proof and write only new TR files. `editor_install_ai` previews first and restricts writes to `INSTALLPATH\\game\\ai\\aom_mcp`; updates need pinned ownership receipt/old hash and external new backup/staging paths (`force=true` skips only the receipt, still inside `aom_mcp`). Never overwrite stock/unregistered AI, elevate, retry or auto-clean retained artifacts. `editor_runtime_probe` generates opt-in own-context XS with fresh KB queries, no context switching/saved-ID dispatch; `aiEcho` file transport/compiler proof unconfirmed. `editor_runtime_report` validates supplied hash/time/run-bound transcript facts, not authenticated engine evidence. `editor_playtest` registers four profiles `uilayouts/playtest-{alt,normal}-en-{2560x1440,1920x1080}.json` (English, Player1/Standard, exact build/hash/pixels; pick the one matching `uiKind`/client size from capabilities `profiles`); public start/inspect/token-bound normal menu Quit passed for each. Loading/defeat/external overlays/other profiles refuse; only host-token-authorized known-playing Quit uses narrow outside-editor input. Poll next gates before following clicks; never repeat queued input. Runtime offsets remain disabled; no debugger, memory writes or arbitrary native getters. See `research/SESSION-WORKFLOWS.md` and `research/RUNTIME-TELEMETRY.md`.
- Writing AI/random-map/trigger XS: look up syscalls and shipped library functions with core `editor_xs_api` (name/filter/kind/context/library). Repo ships signatures + own summaries only (`xs/`); official syscall help and source comments come from the local install at query time. Library functions need `include` relative to `game/random_maps` or `game/ai`. Maintainer refresh after game updates: `--build-xs-api xs/xs_api.json` (summaries in `xs/xs_summaries.json` keyed `library/[Class.]name`).
- Computer-player `.xs` personalities must be under `INSTALLPATH\game\ai` (e.g. `C:\Program Files (x86)\Steam\steamapps\common\Age of Mythology Retold\game\ai`); profile `<id>\ai` did NOT work. Trigger files belong in profile `<id>\trigger`. XS runtime, attack waves and reload persistence remain unverified by tools.
