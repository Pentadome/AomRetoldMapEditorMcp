# Editor workflow: fast, guarded

- Keep one MCP host/stdio connection for each workflow. Group known operations in `editor_batch` (up to 32 steps); avoid one host/model turn per action.
- Default core exposes 72 tools (63 helpers + nine essential native commands). Always-visible `editor_toolset` inspects/switches core/full mid-session; full has 922 tools (including seven full-only session workflow helpers). Changes notify tools/list_changed: refresh tools/list without old cursor. Use standalone mode call, never inside editor_batch. Hidden calls/batch steps fail before effects. Tool sets are not permission sandboxes.
- Find tools from core with `editor_search_tools`: required nonblank `query` (max256), whitespace-separated case-insensitive terms across full-catalog names/descriptions; compact results include `available`/`requiredToolset`, no schemas. offset>=0, limit1..50 (default10); follow nextOffset. No game connection, mode change or match execution. Hidden matches require standalone full switch and fresh tools/list; availability is not runtime readiness.
- For unfamiliar native parameters, read `generated/catalog.json` or narrowly filtered `editor_catalog` (current set only). Switch full when needed; do not page full schema surface for one command. Immutable definitions cached within host.
- Use `editor_pantheon` for exact culture-associated unit/building names (e.g. `greeks`), not guessed spellings/artwork. Metadata-only; no game connection. Union across gods/ages, not current-player trainability. Regenerate/restart if metadata missing/stale.
- Use filtered `editor_prototypes` for trees/resources/wildlife/decorations/other objects; `editor_gods`, `editor_technologies`, `editor_god_powers`, `editor_terrain_types`, `editor_water_types` for other source catalogs. Exact `name` or narrow `filter`; bounded `limit`, follow `nextOffset`. XML detail only when needed. Metadata-only batches need no game. Source names/flags are not runtime IDs or placement proof.
- Inspect start state once. Use one final screenshot after known actions; intermediate screenshots only when next action depends on visible state. Batch `delayMs` can wait for a frame, but acknowledgements still do not prove effects.
- Prefer world-space scene helpers (core) over pixel placement: `editor_place_at_world` (world X/Z, catalog proto check with suggestions, minimap camera move, UI-panel avoidance, returns observed unitId/positionError), `editor_apply_layout` (items or world-unit formation; preview default, apply needs confirmPlacement, footprint issues refuse unless allowIssues), `editor_camera_look_at` (closed-loop minimap clicks, alt-UI 2560×1440 only), `editor_view_info`/`editor_ui_state` (visible ground bounds, panels, cursor), `editor_units_snapshot`+`editor_units_diff` (added/removed/moved/reidentified — undo/redo gives NEW IDs), `editor_scene_summary`, `editor_check_footprints`, `editor_terrain_grid` (heights, flat sites). `editor_delete_units` needs exact {unitId,proto,player} + confirmDestructive; selects via uiLookAtAndSelectUnit, verifies exact selection, DELETE, verifies removal. Raw `editor_place_unit` pixels over UI panels can still place on hidden map behind them. See `research/SCENE-TOOLS.md`.
- Never guess unit IDs from placement order. Use `editor_units` / `editor_inspect_selection` for actual full live IDs/properties; IDs do not persist across reloads. `editor_map_info` gives measured projection/rays/native quantized heights, not terrain-collision or occlusion proof. These reads need reviewed optional layout sections; generator never guesses them.
- Use `editor_dependencies` for source train/build/tech/god paths; potential links, not evaluated current-player trainability. `editor_validate_scenario` is partial/read-only; caller-declared live IDs and supplied controller heuristics only, skipped checks explicit.
- `editor_triggers` structured support is strictly verified TR v12 single Always/CodeSnippet controller. Local patch requires new output/confirmWrite; apply requires confirmDestructive and retains original backup/round-trip files. Unknown shapes refuse; serialization equality is not XS compilation/effect proof.
- Native `uiLoadTriggers` / `uiSaveTriggers` / `saveScenario` receive filename stems, not suffixed filenames: game appends `.trg` / `.mythscn`. Raw trigger import/export require confirmDestructive. Unknown structured original triggers need separately authorized native backup restoration; helper apply does not guess their shapes.
- Selection and undo effects can be queued. Put `delayMs` on the **following read step**, then verify actual IDs/properties; do not repeat mutations from immediate acknowledgements. Placement cleanup clears cursor, but object palette can remain open; inspect before explicit ESC/UI restoration.
- `editor_place_formation` defaults to pure preview. Spacing is client pixels, not world units; count cap32. Actual placement requires preview=false/confirmPlacement and observes IDs; partial effects remain on failure. `editor_save_checkpoint` requires approved new absolute .mythscn path/confirmWrite, unique game-writer staging and verification. No overwrite/retry/automatic rollback. Never exercise these mutations merely to test code on user's current scene without specific live-test authorization and backups.
- Greek infantry building is `MilitaryAcademy`, not Egyptian `Barracks`. Replacement observed with prototype selection → DELETE key → `editor_place_unit`; `uiTransformSelectedUnit(...,-1,false)` did not change selected barracks in that tested context. Do not waste repeated attempts on that unverified path.
- Coordinates are full-resolution client pixels. Multiply half-width screenshot coordinates by two on 2560×1440 client.
- Batch preflights schemas/native confirmations and stops on first error; earlier effects remain. Never blindly retry mutations or entire batches. Keep every hash/thread/editor/foreground/selection guard.
- Use UI Play/Quit for playtest transitions; one native start-test call crashed game. Read-only screenshots work during playtest; mutations remain editor-only.
- Native `loadScenario` tool and shipped expressions referencing it are removed: alternative-UI test crashed game after this call. Full mode/confirmation cannot re-enable it. Normal Load Scenario UI successfully loaded the same edited checkpoint and restored original backup after restart. Wait for loading to finish before scene reads; editor flag/acknowledgement alone does not prove readiness. Core alternative-UI flows tested, not full coverage or an alternative-specific crash cause; see `research/ALTERNATIVE-UI.md`.
- Editor has two UIs: **normal** and **alternative**. Switch: main menu → Settings → UI → scroll to bottom → "Alternative Editor UI". Scene helpers auto-detect the UI from pixel gates (normal: top menu bar; `uilayouts/normal-en-2560x1440.json`) and report `uiKind`; minimap targeting/occluders work in both at 2560×1440. `editor_player_settings`, `editor_playtest`, OCR field presets remain alternative-UI only. Normal UI docks tool panel + list palette along the bottom; PlaceUnit opens them, so placement treats them as occluders.
- World helpers (core, `research/LIVE-WORLD.md`): `editor_edit_mode` reads mode/UI kind/paint selections and `exit=true` leaves any tool (PlaceUnit needs two `editMode("None")`). `editor_paint_world` paints texture/mix/water/forest/cliff along world points (confirmDestructive; current brush; verified tile/object diff). `editor_elevation` set/flatten/smooth an area (brush centers on lower-left node of tile under pointer; edges can bleed ~2 nodes, reported). `editor_transform_unit` moves (moveunit drag) and rotates (`uiRotateSelection` = ±22.5° per call, magnitude ignored). `editor_terrain_info`, `editor_live_players` (no resources: obfuscated), `editor_terrain_catalog` (exact native names, lighting index→name, civ id→name), `editor_overview` (ID-annotated screenshot), `editor_camera_frame`, `editor_resource_balance`, preview-first `editor_mirror_units`/`editor_scatter`.
- Speed checks must not place/delete objects or change triggers. Existing build/self-test/protocol smoke cover code changes; no new framework needed.
- Start unfamiliar work with `editor_capabilities`. Errors carry `code`/`nativeDispatched`/`safeInspection`/`nextAction`; `*_OUTCOME_UNKNOWN` means stop and inspect retained paths. Campaign triggers: `editor_trigger_list` then preview-first `editor_trigger_edit` (expectedSha256+expectedName, new outputPath); `editor_triggers apply` also needs reviewed live export path/hash. Players: `editor_players`/`editor_player_dependency_audit` decode reviewed checkpoint fields; stances 1 ally, 2 enemy, 3 neutral. `editor_set_diplomacy` accepts directed matrix `changes` (one final checkpoint) as well as legacy oneWay/mutual. `editor_player_settings` previews/verifies offline; apply is pinned to 2560×1440 alternative-UI Players Settings, pixel/OCR gates, fresh checkpoint/TR backups and game-written final checkpoint. - Full-only `editor_unit_notes`/`editor_scenario_diff` are hash-pinned saved-file reads, not live identity/complete semantic proof. Diff assertions evaluate all records before paging. `editor_trigger_edit` typed replacements check full ordered ID/owner/proto tuples; cross-trigger copies read immutable pinned sources and use stable handles/original insertion indices. `editor_startup_orders` audits explicit saved pools and preserves jobs; minimum-distance XZ assignments are not pathfinding/runtime proof and write only new TR files. `editor_install_ai` previews first and restricts writes to `INSTALLPATH\\game\\ai\\aom_mcp`; updates need pinned ownership receipt/old hash and external new backup/staging paths. Never overwrite stock/unregistered AI, elevate, retry or auto-clean retained artifacts. `editor_runtime_probe` generates opt-in own-context XS with fresh KB queries, no context switching/saved-ID dispatch; `aiEcho` file transport/compiler proof unconfirmed. `editor_runtime_report` validates supplied hash/time/run-bound transcript facts, not authenticated engine evidence. `editor_playtest` registers only `uilayouts/playtest-alt-en-2560x1440.json` (English alternative UI, Player1/Standard, exact 2560×1440/build/hash/pixels); public start/inspect/token-bound normal menu Quit passed. Loading/defeat/external overlays/other profiles refuse; only host-token-authorized known-playing Quit uses narrow outside-editor input. Poll next gates before following clicks; never repeat queued input. Runtime offsets remain disabled; no debugger, memory writes or arbitrary native getters. See `research/SESSION-WORKFLOWS.md` and `research/RUNTIME-TELEMETRY.md`.
